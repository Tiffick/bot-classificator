============================================================
05_REPORT_FORMAT.txt
Conversation Lab Report Standard
============================================================

1. Назначение

Настоящий документ определяет единый формат всех отчётов Conversation Lab.

Каждый проведённый эксперимент должен завершаться отчётом, оформленным по настоящему стандарту.

Это обеспечивает возможность сравнивать результаты различных тестирований независимо от времени их проведения и версии консультанта.

------------------------------------------------------------
2. Общие требования

Каждый отчёт должен:

• опираться на наблюдаемые факты;

• отделять факты от интерпретаций;

• отделять интерпретации от архитектурных гипотез;

• содержать достаточное количество информации для воспроизведения выводов;

• быть понятным без обращения к внутреннему устройству Conversation Lab.

• указывать, что выводы получены в симуляции пользователя, если тестирование не проводилось с реальным пользователем.

------------------------------------------------------------
3. Структура отчёта

Каждый отчёт должен содержать следующие разделы.

------------------------------------------------------------
3.1 Информация о тестировании

Дата проведения

Идентификатор сценария

Версия консультанта

Commit проекта

Используемая LLM

Версия System Prompt

Версия Conversation Lab

Тип тестирования

Количество сообщений

Причина завершения консультации

------------------------------------------------------------
3.2 Скрытый профиль пользователя

Полный профиль пользователя, созданный Scenario Generator.

Данный раздел публикуется только после завершения консультации.

------------------------------------------------------------
3.3 Полный диалог

Полная переписка пользователя и консультанта без каких-либо изменений.

Каждая реплика должна иметь последовательный номер.

------------------------------------------------------------
3.4 Анализ этапов консультации

Для каждого этапа определяется:

• цель консультанта;

• достигнута ли цель;

• какую новую информацию удалось получить;

• изменилось ли состояние пользователя;

• двигалась ли консультация вперёд.

------------------------------------------------------------
3.5 Обнаруженные проблемы

Каждая проблема оформляется отдельно.

Запрещается объединять несколько различных проблем в один пункт.

------------------------------------------------------------
3.6 Удачные решения

Перечисляются решения консультанта, которые объективно улучшили качество консультации.

------------------------------------------------------------
3.7 Упущенные возможности

Определяются места, где консультант мог получить дополнительную информацию или улучшить консультацию, но не сделал этого.

------------------------------------------------------------
3.8 Анализ каждой проблемы

Каждая проблема анализируется по следующему шаблону.

============================================================

ФАКТ

Наблюдаемое событие диалога.

Факт должен быть проверяемым.

Указываются номера реплик, на которых основан факт.

------------------------------------------------------------

ИНТЕРПРЕТАЦИЯ

Наиболее вероятное объяснение наблюдаемого факта.

Интерпретация не является доказанным фактом.

------------------------------------------------------------

АРХИТЕКТУРНАЯ ГИПОТЕЗА

Предполагаемая причина.

Указывается:

• наиболее вероятный компонент;

• объяснение;

• уровень уверенности;

• поможет ли применение LLM;

• если поможет —

в каком компоненте.

Уровень уверенности указывается по единой шкале:

• низкий — гипотеза основана на ограниченном числе наблюдений;

• средний — гипотеза подтверждается несколькими наблюдениями диалога;

• высокий — гипотеза последовательно подтверждается диалогом и не имеет более вероятного объяснения.

============================================================

------------------------------------------------------------
3.9 Общая оценка консультации

Краткая оценка качества всего пути пользователя.

Не оцениваются отдельные ответы.

Оценивается только консультация целиком.

------------------------------------------------------------
3.10 Итоговые выводы

Формулируются основные выводы тестирования.

Каждый вывод должен опираться на результаты анализа.

------------------------------------------------------------
4. Главный принцип

Conversation Lab оценивает не качество отдельных ответов.

Conversation Lab оценивает изменения, произошедшие с пользователем в результате консультации.

Любой вывод должен быть воспроизводимым.

Любая рекомендация должна иметь наблюдаемое основание.

Факты всегда имеют приоритет над интерпретациями.

Интерпретации всегда имеют приоритет над архитектурными гипотезами.
