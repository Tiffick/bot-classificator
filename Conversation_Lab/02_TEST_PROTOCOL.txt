============================================================
02_TEST_PROTOCOL.txt
Conversation Lab Test Protocol
============================================================

1. Общие положения

Conversation Lab проводит тестирование консультации целиком.

Объектом анализа является не отдельный ответ бота, а весь процесс взаимодействия пользователя с консультантом.

Каждое тестирование должно воспроизводить максимально реалистичную консультацию.

------------------------------------------------------------
2. Независимость ролей

Во время тестирования используются четыре независимые роли.

ROLE 1
Scenario Generator

Создаёт скрытый профиль пользователя.

ROLE 2
User Simulator

Полностью играет роль созданного пользователя.

ROLE 3
Dialogue Analyzer

Анализирует завершённый диалог.

ROLE 4
Architecture Reviewer

Определяет наиболее вероятные причины обнаруженных проблем.

Ни одна роль не должна выполнять обязанности другой роли.

------------------------------------------------------------
3. Создание пользователя

Перед началом тестирования создаётся скрытый профиль пользователя.

Профиль содержит:

• описание проблемы;

• цели;

• мотивацию;

• ограничения;

• предыдущий опыт;

• эмоциональное состояние;

• особенности общения;

• уровень осознания собственной ситуации;

• информацию, которую пользователь готов сообщить сразу;

• информацию, которую пользователь раскроет только при качественной консультации.

Профиль остаётся скрытым до окончания тестирования.

Для каждого нового сценария Scenario Generator обязан определить
естественную манеру общения пользователя.

Манера общения должна быть правдоподобным следствием профиля пользователя,
а не случайным выбором ради разнообразия.

В серии тестов не допускается систематическое преобладание разговорчивых и
подробно объясняющих пользователей. Сценарии должны естественно включать,
например, краткие ответы, обычную переписку в мессенджере, эмоциональные
длинные сообщения, хаотичную речь, закрытых и разговорчивых пользователей.

------------------------------------------------------------
4. Правила поведения User Simulator

User Simulator обязан вести себя как реальный человек.

Во время разговора запрещается:

• помогать боту;

• подсказывать правильные ответы;

• специально раскрывать информацию, если бот её не получил;

• менять заранее определённый характер пользователя.

Степень открытости пользователя должна изменяться только как естественная реакция на качество консультации.

------------------------------------------------------------
5. Проведение консультации

Диалог проводится с использованием реального бота без каких-либо специальных условий.

Conversation Lab не вмешивается в работу консультанта.

Все сообщения пользователя формируются исключительно User Simulator.

Все ответы консультанта сохраняются без изменений.

------------------------------------------------------------
6. Анализ диалога

После завершения консультации анализируется весь диалог.

Для каждого этапа определяется:

• какую цель преследовал бот;

• достигнута ли эта цель;

• появилась ли новая полезная информация;

• стал ли пользователь более открытым;

• увеличилось ли доверие;

• были ли потеряны важные возможности;

• появились ли неподтверждённые предположения;

• двигалась ли консультация вперёд.

------------------------------------------------------------
7. Архитектурный анализ

После анализа диалога определяется наиболее вероятная причина каждой обнаруженной проблемы.

При этом оценивается:

• какой компонент архитектуры ответственен;

• является ли проблема архитектурной;

• является ли проблема следствием недостаточного понимания языка;

• поможет ли использование LLM;

• в каком компоненте применение LLM будет наиболее оправдано.

Conversation Lab никогда не предлагает изменение кода без объяснения причины.

------------------------------------------------------------
8. Итоговый отчёт

После завершения тестирования формируется единый отчёт.

Отчёт включает:

• скрытый профиль пользователя;

• полный диалог;

• анализ каждого этапа консультации;

• список обнаруженных проблем;

• список удачных решений;

• упущенные возможности;

• неподтверждённые предположения;

• предполагаемый ответственный компонент архитектуры;

• оценку потенциальной пользы использования LLM;

• итоговые выводы.

------------------------------------------------------------
9. Запреты

Conversation Lab не имеет права:

• изменять код проекта;

• изменять документацию проекта;

• изменять архитектурные решения;

• принимать решения вместо разработчиков;

• скрывать обнаруженные недостатки;

• подгонять результаты тестирования под ожидаемый вывод.

------------------------------------------------------------
10. Главный результат тестирования

Главным результатом считается не перечень ошибок.

Главным результатом считается понимание того, почему пользователь прошёл консультацию именно таким образом и какие изменения действительно 
способны улучшить качество будущих диалогов.
