============================================================
04_EXECUTION_PROTOCOL.txt
Conversation Lab Execution Protocol
============================================================

1. Назначение

Execution Protocol определяет порядок проведения одного полного тестирования Conversation Lab.

Документ описывает последовательность действий, необходимых для получения объективного результата.

Execution Protocol не определяет критерии оценки консультации.

Критерии оценки определяются документами:

• README.txt

• 01_PHILOSOPHY.txt

• 02_TEST_PROTOCOL.txt

------------------------------------------------------------
2. Подготовка

Перед началом тестирования необходимо:

• запустить тестируемого AI-консультанта;

• убедиться, что используется актуальная версия проекта;

• очистить предыдущую историю тестового пользователя;

• создать нового пользователя для тестирования;

• убедиться, что Conversation Lab не имеет информации о внутренних состояниях консультанта.

------------------------------------------------------------
3. Создание сценария

Conversation Lab создаёт одного нового пользователя.

Профиль пользователя остаётся скрытым до окончания тестирования.

Во время консультации бот не должен получать никакой информации, кроме сообщений пользователя.

------------------------------------------------------------
4. Проведение консультации

Conversation Lab начинает полноценный диалог.

Во время разговора:

• все сообщения пользователя создаются User Simulator;

• все ответы консультанта сохраняются без изменений;

• запрещается вмешательство разработчика;

• запрещается изменение сценария;

• запрещается повторный запуск отдельных сообщений.

Диалог проводится непрерывно.

Для каждого эксперимента Conversation Lab запускает один непрерывный
технический сеанс. Все сообщения сценария передаются в один и тот же активный
DialogEngine в рамках одного процесса и с одним user_id. Нельзя проводить
последовательные ходы отдельными запусками `python -c` или иным способом,
создающим новый процесс между сообщениями.

На каждом ходе Lab сохраняет техническую трассировку: user_id, идентификатор
процесса, SemanticContext, Memory и previous_human_model на входе Human Model
Engine, итоговую Human Model, ReasoningContext, DecisionContext, ImpactContext,
EmotionalContext и финальный ответ Response Engine. Трассировка используется
только для анализа после эксперимента и не должна изменять ход консультации.

------------------------------------------------------------
5. Завершение консультации

Консультация завершается при наступлении одного из условий:

• бот завершил Discovery;

• бот передал пользователя следующему этапу консультации;

• пользователь отказался продолжать разговор;

• достигнуто максимальное количество сообщений;

• произошла критическая ошибка.

После завершения консультации переписка фиксируется без изменений.

------------------------------------------------------------
6. Анализ

После завершения консультации выполняется полный анализ.

Conversation Lab:

• анализирует весь диалог;

• определяет удачные решения;

• определяет обнаруженные проблемы;

• определяет упущенные возможности;

• определяет неподтверждённые предположения;

• выполняет архитектурный анализ;

• оценивает потенциальную пользу использования LLM.

Во время анализа изменение кода запрещено.

------------------------------------------------------------
7. Формирование отчёта

После завершения анализа создаётся единый отчёт.

Отчёт должен содержать:

• дату тестирования;

• идентификатор сценария;

• скрытый профиль пользователя;

• полный диалог;

• анализ консультации;

• архитектурный анализ;

• рекомендации;

• итоговый вывод.

Отчёт сохраняется в папке:

reports/

Каждый отчёт является самостоятельным документом.

------------------------------------------------------------
8. Правила повторного тестирования

После внесения изменений в проект проводится новое независимое тестирование.

Conversation Lab не должна использовать результаты предыдущего тестирования при моделировании нового пользователя.

Каждый новый тест считается независимым экспериментом.

------------------------------------------------------------
9. Главный принцип

Каждое тестирование должно максимально точно воспроизводить консультацию реального человека.

Любое действие, которое делает тест менее реалистичным, считается нарушением Execution Protocol.
