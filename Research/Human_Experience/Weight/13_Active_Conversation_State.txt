ACTIVE CONVERSATION STATE — SEMANTIC CONTRACT

Статус документа:
Рабочая архитектурная модель Active Conversation State.

Документ определяет смысловую ответственность Active Conversation State
между последовательными проходами одного Cognitive Cycle.

Он НЕ является Data Contract.
Он НЕ предписывает конкретные классы, поля, JSON-структуру или способ хранения.


============================================================
НАЗНАЧЕНИЕ
============================================================

Active Conversation State хранит не накопленное понимание человека.

Накопленное понимание конкретного человека относится к Human Model.

Active Conversation State хранит незавершённый смысловой контекст
последнего действия системы, который может понадобиться для правильной
интерпретации следующей реплики пользователя.

Главный вопрос:

"Что из только что сделанного системой должно пережить границу хода,
чтобы следующий Cognitive Cycle правильно понял ответ пользователя?"


============================================================
ГРАНИЦА С HUMAN MODEL
============================================================

HUMAN MODEL отвечает на вопрос:

"Что мы понимаем об этом человеке?"


ACTIVE CONVERSATION STATE отвечает на вопрос:

"На что именно пользователь сейчас может отвечать?"


Active Conversation State НЕ должен дублировать Human Model.

Он не является второй памятью о пользователе
и не должен накапливать историю Discovery.


============================================================
МИНИМАЛЬНОЕ СМЫСЛОВОЕ СОДЕРЖИМОЕ
============================================================

Active Conversation State должен сохранять два смысловых элемента:

1. ACTIVE CONTENT
2. RESPONSE TARGETS


============================================================
1. ACTIVE CONTENT
============================================================

Active Content хранит смысл того,
что система фактически предъявила пользователю
в последнем ходе и что может потребовать реакции пользователя.

Это может быть:

- конкретный вопрос;
- предложенная версия;
- проверяемая связь;
- Recognition;
- рабочая картина Reflection;
- предложение Transition;
- другой смысловой объект,
  на который может отвечать пользователь.

Active Content хранит смысл,
а не обязательно буквальный текст ответа системы.

Полный текст диалога остаётся в Dialogue History.


Если последний ответ системы содержит
несколько независимо разрешимых смыслов,
Active Content не должен храниться
как один неделимый смысловой blob.

Он должен позволять представить
ОДИН ИЛИ НЕСКОЛЬКО АДРЕСУЕМЫХ
СМЫСЛОВЫХ ЭЛЕМЕНТОВ.

Например, Reflection может содержать:

A — изменение в фотографиях;

B — изменение свободы рядом с партнёром;

C — предложенную системой связь между ними.

Следующая реплика пользователя может:

- подтвердить A;
- отвергнуть B;
- скорректировать C;
- согласиться со всей картиной;
- ответить только на одну её часть.

Поэтому отдельные активные смыслы
должны быть различимы внутри ACS.


============================================================
2. RESPONSE TARGETS
============================================================

Response Targets указывают,
какую часть или части Active Content
следующая реплика пользователя
может разрешить или изменить.

Response Target не обязан быть единственным.

Один системный ход может содержать
несколько независимо разрешимых предложений,
вариантов или связей.

Например, Recognition:

"Может быть, стало сложнее фотографироваться,
раздеваться перед партнёром
или участвовать в каких-то активностях?"

может получить ответ:

"Фото — да. Остальное нет."

В этом случае пользовательская реплика
разрешает несколько targets независимо.

Поэтому ACS должен позволять:

RESPONSE TARGETS
=
one or more references
to active semantic items / relations.


Response Targets должны позволить
следующему Cognitive Cycle понять:

- к чему относится короткий ответ;
- какие части предыдущего системного хода
  пользователь подтверждает;
- какие отвергает;
- какие уточняет;
- какие оставляет неопределёнными;
- какие вообще не были затронуты ответом.


============================================================
АДРЕСУЕМОСТЬ
============================================================

Каждый независимо разрешимый
active semantic item должен иметь
стабильную идентичность
в пределах текущего Active Conversation State.

Конкретная техническая форма идентификатора
в этом документе не определяется.

Требование только смысловое:

Integration + State Reconciliation
должен иметь возможность сопоставить
часть новой пользовательской реплики
с конкретным элементом или связью,
предъявленной системой в предыдущем ходе.


============================================================
ЧТО НЕ ЯВЛЯЕТСЯ ОБЯЗАТЕЛЬНОЙ ЧАСТЬЮ МИНИМУМА
============================================================

Тип действия:

Recognition
Reflection
Personal Meaning
Transition
и т. д.

может быть полезен как техническое metadata,
но сам по себе не является достаточным
и не считается обязательной частью минимального
смыслового состояния.

Причина:

action = Recognition

не объясняет,
какую именно версию пользователь сейчас
подтверждает или отвергает.

action = Reflection

не объясняет,
какую именно часть картины
пользователь сейчас корректирует.

Смысл активного действия должен находиться
в Active Content и Response Targets.


============================================================
НЕОПРЕДЕЛЁННЫЕ ОТВЕТЫ
============================================================

Active Conversation State позволяет определить,
НА ЧТО относится ответ пользователя.

Он не позволяет автоматически определить,
КАК именно пользователь это сказал,
если текст не даёт достаточной информации.

Например:

"может быть"

может относиться к конкретной версии,
потому что Response Target это показывает.

Но сама степень согласия может оставаться неопределённой.

Active Conversation State не должен превращать
неоднозначную текстовую реакцию
в подтверждение или отрицание.

Неопределённость интерпретации сохраняется
на этапе Integration + State Reconciliation.

Уточнение необходимо только тогда,
когда разные допустимые интерпретации
могут изменить следующий Decision.


============================================================
ЕСЛИ TARGET НЕ ПОЛУЧИЛ ОТВЕТ
============================================================

Пользователь не обязан отвечать
на активный Response Target.

Он может:

- сменить тему;
- добавить новый материал;
- задать встречный вопрос;
- отказаться обсуждать тему;
- вернуться к более старому материалу.

Integration + State Reconciliation
не должен принудительно трактовать
любую новую реплику как ответ
на текущий Response Target.

Неразрешённый target
не обязан автоматически переноситься
в следующий Active Conversation State.

Если незавершённая системная версия
достаточно значима для будущего понимания,
она может существовать в Human Model
с соответствующим происхождением и статусом.

ACS не является backlog
всех незакрытых вопросов и гипотез.


============================================================
ЖИЗНЕННЫЙ ЦИКЛ
============================================================

В конце Cognitive Cycle:

Response
↓
Persist
↓
создаётся новый Active Conversation State


В начале следующего Cognitive Cycle:

User Message
+
Human Model
+
Active Conversation State
+
Human Experience

↓
Perception
↓
Integration + State Reconciliation


После интеграции новой реплики
предыдущее Active Conversation State
считается отработанным.

Новый Active Conversation State создаётся
только из нового действия системы.


============================================================
КЛЮЧЕВОЙ ПРИНЦИП
============================================================

Active Conversation State — это не память о разговоре.

Это смысловая закладка между двумя соседними ходами:

"Вот какие смыслы система только что вынесла
в активный диалог,
и вот на какие из них пользователь сейчас может отвечать."


Уточнённый рабочий минимальный контракт:

ACTIVE CONTENT
=
one or more addressable semantic items

+

RESPONSE TARGETS
=
one or more references
to active items / relations
