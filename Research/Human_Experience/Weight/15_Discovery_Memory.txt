DISCOVERY MEMORY — SEMANTIC ARCHITECTURE

Статус документа:
Рабочая архитектурная модель памяти Discovery.

Документ связывает Cognitive Cycle,
Human Model, Active Conversation State,
Dialogue History и Human Experience
в одну модель памяти между ходами.

Он НЕ является Data Contract.
Он НЕ предписывает конкретные классы, поля,
JSON-структуру, базу данных или способ сериализации.


============================================================
НАЗНАЧЕНИЕ
============================================================

Discovery должен продолжать разговор,
не начиная понимание человека заново на каждом ходе.

При этом разные виды информации
не должны смешиваться в одну общую память.

Система использует четыре смыслово разные опоры:

1. HUMAN MODEL
2. ACTIVE CONVERSATION STATE
3. DIALOGUE HISTORY
4. HUMAN EXPERIENCE

Каждая из них имеет отдельную ответственность.


============================================================
1. HUMAN MODEL
============================================================

Human Model хранит накопленное рабочее понимание
КОНКРЕТНОГО человека.

Он отвечает на вопрос:

"Что мы сейчас понимаем об этом человеке
и на каком основании?"

В Human Model относятся результаты разговора,
которые могут быть нужны после текущего хода:

- пользовательский опыт;
- изменения;
- Before → Now;
- Personal Meaning;
- Desired Change / Return;
- Previous Attempts;
- Barriers;
- пользовательские интерпретации;
- значимые связи;
- поддержанные системные версии;
- отвергнутые системные версии;
- существенные неопределённости;
- другие элементы рабочей картины конкретного человека.

Human Model не является анкетой
и не обязан иметь заранее заполненный набор категорий.


============================================================
2. ACTIVE CONVERSATION STATE
============================================================

Active Conversation State хранит
незавершённый смысловой контекст
ПОСЛЕДНЕГО действия системы.

Он отвечает на вопрос:

"На что именно пользователь сейчас может отвечать?"

Минимальный смысловой контракт:

ACTIVE CONTENT
+
RESPONSE TARGET

Active Conversation State является временной
смысловой закладкой между соседними ходами.

После Integration + State Reconciliation
предыдущее состояние считается отработанным.

Оно не должно превращаться
в накопительную память о человеке.


============================================================
3. DIALOGUE HISTORY
============================================================

Dialogue History хранит фактическую последовательность
реплик пользователя и системы.

Он отвечает на вопрос:

"Что буквально происходило в разговоре?"

Dialogue History является первичным контекстом,
но не заменяет Human Model.

Система не должна каждый раз заново строить
всё понимание человека исключительно
из полного текста истории.

Human Model сохраняет интегрированный результат понимания.

Dialogue History сохраняет исходный разговор
и позволяет при необходимости свериться
с формулировками и ближайшим контекстом.


============================================================
4. HUMAN EXPERIENCE
============================================================

Human Experience не является памятью
о конкретном пользователе.

Это профессиональная карта возможного опыта.

Она отвечает на вопрос:

"Что вообще может встречаться у людей
в похожей ситуации и куда иногда полезно посмотреть?"

Human Experience может помогать:

- выбирать направление исследования;
- делать Recognition;
- замечать возможные области постепенной адаптации;
- предлагать контекстно близкие варианты для узнавания.

Human Experience не может самостоятельно
создавать элементы Human Model.


============================================================
ГЛАВНЫЕ ГРАНИЦЫ
============================================================

HUMAN MODEL
≠
DIALOGUE HISTORY

Рабочее понимание человека
не равно стенограмме разговора.


HUMAN MODEL
≠
ACTIVE CONVERSATION STATE

Накопленное понимание человека
не равно незавершённому контексту последнего хода.


HUMAN MODEL
≠
HUMAN EXPERIENCE

То, что возможно у людей вообще,
не является фактом о конкретном пользователе.


ACTIVE CONVERSATION STATE
≠
DIALOGUE HISTORY

Смысловая закладка последнего действия
не является копией последней реплики системы.


============================================================
ОДИН ПРОХОД ПАМЯТИ
============================================================

На вход нового Cognitive Cycle поступают:

USER MESSAGE
+
HUMAN MODEL
+
ACTIVE CONVERSATION STATE
+
HUMAN EXPERIENCE

Dialogue History доступна как контекст разговора.


PERCEPTION понимает новую реплику.


INTEGRATION + STATE RECONCILIATION:

- связывает новую реплику с Active Conversation State;
- различает пользовательский материал
  и ранее предложенный системой;
- учитывает подтверждение, отказ, коррекцию
  и неопределённость;
- обновляет рабочее понимание человека.


После Integration:

Human Model содержит обновлённое
накопленное понимание.

Предыдущий Active Conversation State
считается отработанным.


FORMULATION использует Human Model
для построения текущей рабочей картины.


DECISION выбирает следующий полезный ход.


RESPONSE формулирует его.


PERSIST сохраняет:

1. UPDATED HUMAN MODEL

2. NEW ACTIVE CONVERSATION STATE

Dialogue History получает новые реплики.

Human Experience не изменяется
из-за единичного разговора с пользователем.


============================================================
ЧТО НЕ НУЖНО ХРАНИТЬ КАК ОТДЕЛЬНУЮ ПАМЯТЬ
============================================================

На текущем уровне архитектуры
не требуется отдельная накопительная память для:

- Perception;
- Formulation;
- Decision;
- Impact;
- Emotional Adaptation;
- Response.

Это результаты мышления текущего Cognitive Cycle.

Если какой-либо результат должен влиять
на будущие ходы, он должен попасть
в соответствующее место:

- понимание человека → Human Model;
- незавершённый контекст последнего действия
  → Active Conversation State;
- буквальная последовательность разговора
  → Dialogue History.

Новая сущность памяти создаётся только тогда,
когда существует информация,
которая должна пережить границу хода
и не принадлежит ни одной из этих ответственностей.


============================================================
DISCOVERY PROGRESS
============================================================

Discovery Progress не должен существовать
как анкета вида:

problem = true
motivation = true
pain = true
limitations = true
discovery_complete = true

Прогресс Discovery выражается
качеством накопленного Human Model
и текущей Formulation.

Decision оценивает Sufficiency динамически:

"Добавит ли ещё один исследовательский ход
значимое понимание?"

Поэтому завершённость Discovery
не является отдельным обязательным
персистентным булевым состоянием.


============================================================
МИНИМАЛЬНАЯ ПЕРСИСТЕНТНАЯ МОДЕЛЬ
============================================================

После каждого хода Discovery
обязательно переживают границу цикла:

HUMAN MODEL
+
ACTIVE CONVERSATION STATE
+
DIALOGUE HISTORY


HUMAN EXPERIENCE существует отдельно
как профессиональная база знаний
и подключается к каждому новому Cognitive Cycle.


============================================================
КЛЮЧЕВОЙ ПРИНЦИП
============================================================

Память Discovery разделяется
не по удобству реализации,
а по смысловой ответственности.

Human Model:
"Что мы поняли о человеке."

Active Conversation State:
"На что он сейчас отвечает."

Dialogue History:
"Что буквально было сказано."

Human Experience:
"Что вообще бывает у людей."

Этого набора достаточно
для перехода к проектированию Data Model,
если последующая проверка не обнаружит
информацию, которая должна переживать границу хода
и не принадлежит ни одному из этих четырёх источников.
