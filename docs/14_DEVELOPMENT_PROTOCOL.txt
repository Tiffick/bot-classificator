===============================================================================
DEVELOPMENT PROTOCOL
===============================================================================

Назначение
-------------------------------------------------------------------------------

Данный документ определяет правила разработки AI Consultant.

Архитектура проекта считается утвержденной.

Все последующие изменения должны соответствовать документации,
расположенной в папке /docs.

===============================================================================
ПРИНЦИПЫ РАЗРАБОТКИ
===============================================================================

1. Архитектура первична.

Код реализует архитектуру.

Архитектура не изменяется ради удобства реализации.

-------------------------------------------------------------------------------

2. Один Engine — одна задача.

Каждый Engine реализуется отдельно.

Реализация нового Engine начинается только после завершения предыдущего.

-------------------------------------------------------------------------------

3. Data Contracts неизменяемы.

Engine не изменяет Context предыдущего Engine.

Каждый Engine создает только собственный Context.

-------------------------------------------------------------------------------

4. Маленькие итерации.

Каждое изменение должно быть небольшим,
понятным и легко проверяемым.

-------------------------------------------------------------------------------

5. После каждой реализации проводится проверка.

Проверяется:

• соответствие документации;

• отсутствие нарушения архитектуры;

• прохождение тестов;

• совместимость с существующим кодом.

===============================================================================
РОЛИ
===============================================================================

Архитектор

• развитие архитектуры;

• контроль документации;

• контроль соответствия реализации.

-------------------------------------------------------------------------------

Инженер реализации

• реализация Engine;

• рефакторинг;

• тестирование;

• исправление ошибок.

-------------------------------------------------------------------------------

Product Owner

• определение целей продукта;

• принятие архитектурных решений;

• финальное утверждение изменений.

===============================================================================
ГЛАВНОЕ ПРАВИЛО
===============================================================================

Документация определяет архитектуру.

Код реализует документацию.

При любом расхождении между кодом и документацией
ошибкой считается код.

===============================================================================



===============================================================================
CHANGE CONTROL
===============================================================================

Любое изменение архитектуры проходит четыре этапа.

1.
Предложение.

2.
Обсуждение.

3.
Обновление документации.

4.
Только после этого изменение кода.

Изменение архитектуры через код запрещено.
