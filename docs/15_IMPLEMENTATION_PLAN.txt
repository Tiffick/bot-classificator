===============================================================================
AI CONSULTANT — IMPLEMENTATION PLAN
===============================================================================

Статус: главный рабочий план реализации.

Назначение
-------------------------------------------------------------------------------

Этот документ определяет последовательность реализации утверждённой
архитектуры из /docs. Он не изменяет архитектуру и не заменяет Development
Protocol. Каждый Phase является отдельной безопасной итерацией: после него
проект запускается, существующие проверки проходят, а изменения можно
зафиксировать отдельным commit и push.

Общие правила
-------------------------------------------------------------------------------

• Источник архитектурной истины — /docs.
• Не реализовывать логику будущих Engine раньше завершения предыдущего Phase.
• Не смешивать реализацию Engine, несвязанный рефакторинг и изменение
  архитектуры в одной итерации.
• Каждый новый или изменённый Engine получает изолированные тесты.
• Сквозная проверка всегда использует тестовую заглушку LLM; живой API не
  является обязательной проверкой Phase.
• До отдельного архитектурного решения Transfer Engine не входит в данный
  план: актуальный Consultative Loop и Engine Architecture описывают семь
  Engine, заканчивающихся Response Engine.

Зафиксированные вопросы, не решаемые этим планом
-------------------------------------------------------------------------------

1. В /docs существует расхождение: 03_AI CONSULTANT ARCHITECTURE.txt
упоминает Transfer Engine, тогда как 04_CONSULTATIVE LOOP.txt и
06_ENGINE_ARCHITECTURE.txt задают семиэтапный цикл без него.

2. README.txt содержит устаревшее соответствие номеров и названий документов
06–13. Исправление документации возможно только отдельным архитектурным
решением.

Эти вопросы не блокируют реализацию семи Engine. При появлении зависимости от
Transfer Engine работа останавливается до решения Архитектора.
