03_План рефакторинга.txt

Версия: 1.0
Статус: Утверждён после завершения первого архитектурного аудита.

=========================================================
Цель документа
=========================================================

Этот документ определяет порядок развития проекта.

Главный принцип:

Сначала архитектура.
Потом код.

Мы не переписываем проект.

Мы постепенно приводим его к архитектуре цифрового консультанта.

Каждый этап должен:

- быть небольшим;
- заканчиваться рабочим проектом;
- сопровождаться проверкой;
- завершаться отдельным Git-коммитом.

=========================================================
Главный принцип рефакторинга
=========================================================

Запрещается:

- большие переписывания файлов;
- изменение нескольких архитектурных узлов одновременно;
- рефакторинг "на будущее";
- изменение поведения без необходимости.

Разрешается:

- небольшие локальные изменения;
- выделение ответственности;
- перенос логики без изменения поведения;
- создание новых модулей с последующим постепенным переносом кода.

=========================================================
Этап 1
Завершение аудита
=========================================================

Статус:

Выполнен.

Результат:

✓ Архитектурный аудит.

✓ Карта ответственности модулей.

=========================================================
Этап 2
Разделение ответственности
=========================================================

Цель:

Перестать концентрировать всю архитектуру внутри dialog_engine.py.

На этом этапе поведение бота измениться не должно.

Будут только выделяться отдельные зоны ответственности.

Приоритет:

Очень высокий.

=========================================================
Этап 3
Выделение отдельных движков
=========================================================

Планируется создание следующих компонентов.

1. Human Model

Отвечает только на вопрос:

"Что мы сейчас понимаем о человеке?"

Не хранит историю.

Не отвечает пользователю.

Не принимает решений.

---------------------------------------------------------

2. Decision Engine

Отвечает только на вопрос:

"Что сейчас лучше сделать?"

Не формулирует текст.

Не обновляет память.

---------------------------------------------------------

3. Emotional Engine

Отвечает только на вопрос:

"Как это лучше сказать именно этому человеку?"

---------------------------------------------------------

4. Impact Engine

Определяет:

Какое главное осознание должен получить человек после текущего сообщения.

---------------------------------------------------------

5. Semantic Engine

Отвечает за понимание смысла сообщения пользователя.

Не принимает решений.

=========================================================
Этап 4
Рефакторинг памяти
=========================================================

Текущая проблема.

user_memory одновременно хранит:

- профиль;
- состояние;
- историю;
- служебные данные.

Планируется разделение.

Human Profile

↓

Conversation State

↓

Conversation History

При этом внешнее поведение проекта измениться не должно.

=========================================================
Этап 5
Рефакторинг Prompt Layer
=========================================================

После появления отдельных движков будет постепенно уменьшаться роль System Prompt.

В будущем:

System Prompt будет отвечать только на вопрос:

"Кто такой консультант?"

Вся остальная ответственность будет вынесена в специализированные компоненты.

=========================================================
Этап 6
Развитие консультанта
=========================================================

После завершения архитектурного разделения начнётся развитие самого консультанта.

Например:

- более глубокое понимание мотивации;
- построение гипотез;
- определение стадии готовности;
- персонализация консультации;
- адаптация стратегии общения;
- обучение на истории консультации.

=========================================================
Правила каждого изменения
=========================================================

Перед изменением:

1. Анализ.
2. План.
3. Минимальное изменение.

После изменения:

1. Запуск проекта.
2. Проверка работы.
3. Git Commit.
4. Git Push.

Только после этого следующий шаг.

=========================================================
Что НЕ делаем
=========================================================

Не переписываем dialog_engine.py целиком.

Не переписываем System Prompt.

Не меняем архитектуру одним большим коммитом.

Не создаём сложные абстракции заранее.

=========================================================
Первый практический этап
=========================================================

Первой задачей после утверждения данного плана станет не добавление новой функциональности.

Первой задачей станет создание архитектурного каркаса будущих движков без изменения поведения системы.

Это позволит в дальнейшем переносить логику постепенно, сохраняя стабильность проекта.

=========================================================
Главная цель проекта
=========================================================

Мы строим не чат-бота.

Мы строим цифрового консультанта.

Главная ценность проекта заключается не в генерации текста.

Главная ценность проекта — воспроизведение процесса мышления опытного консультанта.

Каждое изменение проекта должно приближать систему именно к этой цели.
