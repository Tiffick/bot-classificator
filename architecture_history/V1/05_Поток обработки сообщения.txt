05_Поток обработки сообщения.txt

Версия: 1.0
Статус: Архитектурная спецификация.

=========================================================
Назначение документа
=========================================================

Документ определяет полный жизненный цикл обработки одного сообщения пользователя.

Главный принцип:

Ответ пользователю является последним этапом работы системы.

До этого система должна пройти несколько этапов понимания и принятия решения.

Каждый этап отвечает только за одну ответственность.

=========================================================
Главная идея
=========================================================

Проект не должен отвечать сразу после получения сообщения.

Он должен сначала "подумать".

Этот процесс мышления состоит из последовательных независимых этапов.

=========================================================
Полный поток обработки
=========================================================

Сообщение пользователя

↓

Semantic Engine

↓

Human Model Engine

↓

Decision Engine

↓

Impact Engine

↓

Emotional Engine

↓

Response Generator

↓

Memory Update

↓

Ответ пользователю

=========================================================
Этап 1
Semantic Engine
=========================================================

Главный вопрос:

"Что именно хотел сказать пользователь?"

Ответственность:

- анализ смысла сообщения;
- определение ключевых фактов;
- определение эмоциональной окраски;
- определение намерения;
- выявление новых данных.

Не принимает решений.

Не отвечает пользователю.

Результат:

Семантическое представление сообщения.

=========================================================
Этап 2
Human Model Engine
=========================================================

Главный вопрос:

"Что теперь изменилось в моём понимании человека?"

Использует:

- профиль;
- память;
- историю;
- результат Semantic Engine.

Формирует новую Human Model.

Не принимает решений.

Не пишет ответы.

=========================================================
Этап 3
Decision Engine
=========================================================

Главный вопрос:

"Что сейчас будет наиболее полезным?"

Возможные решения:

- продолжить исследование;
- уточнить информацию;
- изменить направление разговора;
- подтвердить гипотезу;
- усилить осознание;
- перейти к следующему этапу консультации.

Decision Engine не формулирует текст.

Он принимает только решение.

=========================================================
Этап 4
Impact Engine
=========================================================

Главный вопрос:

"Что человек должен понять после моего ответа?"

Ответственность:

Определение главного психологического эффекта текущего ответа.

Например:

- почувствовать понимание;
- увидеть противоречие;
- осознать причину проблемы;
- почувствовать надежду;
- принять необходимость изменений.

Impact Engine работает не с текстом.

Он работает с целью воздействия.

=========================================================
Этап 5
Emotional Engine
=========================================================

Главный вопрос:

"Как лучше сказать выбранную мысль именно этому человеку?"

Учитывает:

- Human Model;
- выбранное решение;
- требуемый эффект.

Определяет:

- стиль общения;
- уровень мягкости;
- глубину эмпатии;
- темп разговора;
- допустимый уровень давления.

Не принимает решений.

Не изменяет стратегию консультации.

=========================================================
Этап 6
Response Generator
=========================================================

Главный вопрос:

"Как сформулировать окончательный ответ?"

Использует результаты всех предыдущих этапов.

Именно здесь в будущем может использоваться LLM.

LLM не принимает архитектурных решений.

Она формулирует текст.

=========================================================
Этап 7
Memory Update
=========================================================

После формирования ответа система обновляет память.

Обновляются только подтверждённые данные.

Никогда не сохраняются:

- неподтверждённые гипотезы;
- временные выводы;
- внутренние рассуждения системы.

=========================================================
Главный принцип взаимодействия
=========================================================

Каждый следующий этап получает результат предыдущего.

Ни один этап не должен обращаться напрямую к этапам, расположенным дальше по цепочке.

Это делает архитектуру:

- понятной;
- тестируемой;
- расширяемой;
- устойчивой к изменениям.

=========================================================
Что это меняет
=========================================================

Сегодня dialog_engine.py выполняет почти весь этот поток самостоятельно.

После завершения рефакторинга каждый этап станет отдельным модулем.

dialog_engine.py превратится в координатор процесса.

Он больше не будет содержать основную бизнес-логику.

=========================================================
Главный вывод
=========================================================

Цифровой консультант — это не один большой интеллект.

Это последовательность специализированных интеллектуальных этапов.

Каждый этап отвечает только на один вопрос.

Именно совместная работа этих этапов создаёт ощущение мышления опытного консультанта.
