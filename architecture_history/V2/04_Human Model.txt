04_Human Model.txt

Версия: 2.0
Статус: Центральная архитектурная спецификация.

=========================================================
Назначение
=========================================================

Human Model — это центральная модель понимания человека.

Она является главным объектом всей архитектуры цифрового консультанта.

Все интеллектуальные компоненты системы существуют только для того, чтобы построить, уточнить или использовать Human Model.

Ответ пользователю является следствием состояния Human Model.

=========================================================
Главный принцип
=========================================================

После каждого сообщения консультант сначала отвечает самому себе:

"Что я теперь понимаю об этом человеке?"

Ответом на этот вопрос является Human Model.

Каждое новое сообщение должно не просто продолжать разговор.

Оно должно увеличивать глубину понимания человека.

=========================================================
Что такое Human Model
=========================================================

Human Model — это не база данных.

Не профиль пользователя.

Не память.

Не история сообщений.

Human Model — это текущее состояние понимания человека системой.

Она существует только для принятия интеллектуальных решений.

=========================================================
Главные свойства Human Model
=========================================================

Human Model должна быть:

- живой;
- вероятностной;
- постоянно изменяющейся;
- независимой от Telegram;
- независимой от Prompt;
- независимой от конкретной LLM.

После каждого сообщения она может измениться.

=========================================================
Структура Human Model
=========================================================

---------------------------------------------------------
1. Facts
---------------------------------------------------------

Факты, подтверждённые пользователем.

Например:

- имя;
- возраст;
- рост;
- вес;
- семейное положение;
- профессия;
- подтверждённые жизненные события.

Факты имеют максимальную степень достоверности.

=========================================================

---------------------------------------------------------
2. Unknowns
---------------------------------------------------------

Список того, что системе пока неизвестно.

Например:

- длительность проблемы;
- предыдущие попытки;
- ограничения;
- уровень поддержки;
- отношение семьи;
- текущая мотивация.

Unknowns позволяют системе понимать собственные пробелы.

=========================================================

---------------------------------------------------------
3. Hypotheses
---------------------------------------------------------

Главная часть Human Model.

Гипотеза — это предположение консультанта.

Например:

- боится очередной неудачи;
- испытывает чувство вины;
- проблема эмоциональная;
- недостаточно поддержки;
- главная мотивация — здоровье;
- главная мотивация — внешний вид.

Гипотезы никогда автоматически не становятся фактами.

=========================================================

---------------------------------------------------------
4. Confidence
---------------------------------------------------------

Каждая гипотеза имеет уровень уверенности.

Например:

0.15

0.42

0.78

0.95

Уверенность постоянно изменяется по мере развития консультации.

=========================================================

---------------------------------------------------------
5. Pain Map
---------------------------------------------------------

Карта боли показывает, что именно причиняет человеку страдание.

Например:

- внешний вид;
- одежда;
- энергия;
- здоровье;
- сон;
- ограничения;
- самооценка;
- отношения.

Это не медицинская карта.

Это карта субъективного переживания человека.

=========================================================

---------------------------------------------------------
6. Motivation Map
---------------------------------------------------------

Хранит не цели.

А причины целей.

Например:

Хочу похудеть.

↓

Чтобы нравиться себе.

↓

Чтобы чувствовать уверенность.

↓

Чтобы не избегать общения.

Именно Motivation Map определяет дальнейшую стратегию консультации.

=========================================================

---------------------------------------------------------
7. Consultation Stage
---------------------------------------------------------

Human Model должна понимать текущую стадию консультации.

Например:

- знакомство;
- исследование;
- формирование гипотез;
- осознание;
- принятие решения;
- сопровождение.

Это состояние процесса консультирования, а не программы.

=========================================================

---------------------------------------------------------
8. Understanding Score
---------------------------------------------------------

Human Model должна оценивать собственную полноту понимания.

Это не одно число.

Оно складывается из нескольких компонентов.

Например:

Проблема.............95%

Мотивация............81%

Боль.................90%

Страх................42%

Самовосприятие.......37%

Ограничения..........63%

Доверие..............58%

Именно эти показатели определяют дальнейшие действия системы.

=========================================================
Главный принцип принятия решений
=========================================================

Decision Engine не принимает решения на основании сообщений пользователя.

Он принимает решения на основании Human Model.

Если уровень понимания недостаточен —

система продолжает исследование.

Если понимание достигло необходимой глубины —

система переходит к следующему этапу консультации.

=========================================================
Кто создаёт Human Model
=========================================================

Human Model создаётся исключительно HumanModelEngine.

Никакой другой модуль не имеет права самостоятельно создавать или изменять её структуру.

Каждый компонент использует одну и ту же Human Model.

Никакой компонент не создаёт собственную модель понимания человека.

=========================================================
Чего Human Model никогда не хранит
=========================================================

Human Model никогда не содержит:

- историю сообщений;
- технические данные Telegram;
- last_question;
- discovery_complete;
- внутренние служебные флаги;
- Prompt;
- текст ответов;
- системные настройки.

Эти данные принадлежат другим компонентам архитектуры.

=========================================================
Главный принцип развития
=========================================================

Главная задача проекта —

не научиться лучше отвечать.

Главная задача —

научиться лучше понимать человека.

Именно Human Model является мерой этого понимания.

Все остальные компоненты существуют только для её развития.
