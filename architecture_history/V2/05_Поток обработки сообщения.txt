05_Поток обработки сообщения.txt

Версия: 2.0
Статус: Архитектурная спецификация.

=========================================================
Назначение документа
=========================================================

Документ определяет полный жизненный цикл обработки одного сообщения пользователя.

Главный принцип:

Ответ пользователю является последним этапом работы системы.

Главная задача системы — не ответить.

Главная задача — улучшить понимание человека.

=========================================================
Главная идея
=========================================================

После получения каждого сообщения система проходит последовательность интеллектуальных этапов.

Каждый этап отвечает только за одну ответственность.

Все этапы работают вокруг одного центрального объекта — Human Model.

Именно состояние Human Model определяет дальнейшие действия консультанта.

=========================================================
Общий цикл обработки
=========================================================

Сообщение пользователя

↓

Semantic Engine

↓

HumanModelEngine

↓

Reasoning Engine

↓

Decision Engine

↓

Impact Engine

↓

Emotional Engine

↓

Response Generator

↓

Memory Update

↓

Ответ пользователю

=========================================================
Центральный принцип архитектуры
=========================================================

Все интеллектуальные компоненты работают не друг с другом.

Они работают через Human Model.

Никакой Engine не принимает решения только на основании сообщения пользователя.

Каждое решение принимается на основании текущего понимания человека.

=========================================================
Этап 1
Semantic Engine
=========================================================

Главный вопрос:

"Что именно сообщил пользователь?"

Ответственность:

- анализ смысла сообщения;
- извлечение фактов;
- определение эмоциональной окраски;
- выявление намерения;
- выделение новой информации.

Результат:

Семантическое представление сообщения.

Semantic Engine ничего не знает о стратегии консультации.

=========================================================
Этап 2
HumanModelEngine
=========================================================

Главный вопрос:

"Что изменилось в моём понимании человека?"

Использует:

- профиль;
- память;
- историю;
- результат Semantic Engine.

Формирует новую Human Model.

На этом этапе ещё не принимаются никакие решения.

=========================================================
Этап 3
Reasoning Engine
=========================================================

Главный вопрос:

"Как изменилось моё понимание человека?"

Reasoning Engine является главным аналитическим модулем системы.

Он не анализирует сообщение пользователя.

Он анализирует Human Model.

Именно здесь происходит настоящее мышление консультанта.

Reasoning Engine:

- усиливает существующие гипотезы;
- ослабляет неподтверждённые гипотезы;
- создаёт новые гипотезы;
- пересчитывает уровень уверенности;
- определяет области максимальной неопределённости;
- оценивает полноту понимания человека;
- обновляет Understanding Score.

Главная задача Reasoning Engine —

не решить, что сказать.

А понять, что теперь стало известно о человеке и чего система всё ещё не понимает.

После завершения работы Reasoning Engine Human Model считается актуальной.

Именно её получает Decision Engine.

=========================================================
Этап 4
Decision Engine
=========================================================

Главный вопрос:

"Какой следующий шаг даст максимальное увеличение понимания человека?"

Decision Engine принимает решения исключительно на основании Human Model.

Он не анализирует сообщения пользователя.

Он получает уже готовую модель понимания человека после работы Reasoning Engine.

Decision Engine определяет:

- какая область Human Model имеет максимальную неопределённость;
- нужно ли продолжать исследование;
- какую гипотезу необходимо проверить;
- достаточно ли понимания для перехода к следующему этапу консультации;
- какое действие сейчас принесёт максимальный прирост понимания человека.

Decision Engine не формулирует текст.

Он принимает только решение.

=========================================================
Этап 5
Impact Engine
=========================================================

Главный вопрос:

"Что человек должен осознать после моего ответа?"

Impact Engine определяет не текст.

Он определяет цель психологического воздействия.

Например:

- почувствовать понимание;
- увидеть противоречие;
- осознать истинную причину проблемы;
- почувствовать надежду;
- увидеть собственные возможности.

Impact Engine начинает играть значимую роль только после накопления достаточной глубины Human Model.

=========================================================
Этап 6
Emotional Engine
=========================================================

Главный вопрос:

"Как лучше передать выбранную мысль именно этому человеку?"

Использует:

- Human Model;
- решение Decision Engine;
- цель Impact Engine.

Определяет:

- стиль общения;
- глубину эмпатии;
- темп разговора;
- эмоциональный тон;
- уровень поддержки.

Emotional Engine ничего не решает.

Он определяет форму передачи выбранной мысли.

=========================================================
Этап 7
Response Generator
=========================================================

Главный вопрос:

"Как сформулировать окончательный ответ?"

Использует результаты всех предыдущих этапов.

На этом этапе может использоваться LLM.

LLM не принимает архитектурных решений.

Она только формулирует текст.

=========================================================
Этап 8
Memory Update
=========================================================

После формирования ответа обновляется память.

Сохраняются только подтверждённые данные.

Никогда не сохраняются:

- неподтверждённые гипотезы;
- внутренние рассуждения;
- промежуточные выводы;
- значения уверенности.

Human Model строится заново при каждом новом сообщении.

=========================================================
Главный принцип взаимодействия
=========================================================

Каждый Engine имеет только одну ответственность.

Каждый Engine работает через Human Model.

Никакой Engine не должен самостоятельно изменять стратегию работы других компонентов.

Это обеспечивает:

- прозрачность архитектуры;
- тестируемость;
- независимость компонентов;
- постепенное развитие проекта.

=========================================================
Роль dialog_engine.py
=========================================================

dialog_engine.py больше не является местом принятия решений.

Его задача —

координировать последовательность работы специализированных компонентов.

По мере развития архитектуры вся интеллектуальная логика постепенно переносится в отдельные Engine.

=========================================================
Главный вывод
=========================================================

Архитектура V1 представляла собой последовательность обработки сообщений.

Архитектура V2 представляет собой цикл постепенного построения понимания человека.

Ответ пользователю является не целью процесса.

Он является естественным следствием состояния Human Model.
