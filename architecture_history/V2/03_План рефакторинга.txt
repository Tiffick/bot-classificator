03_План рефакторинга

Версия: 2.0
Статус: Утверждён после перехода к архитектуре V2.

=========================================================
Цель документа
=========================================================

Этот документ определяет порядок дальнейшего развития проекта.

Главный принцип:

Сначала мышление.
Потом архитектура.
Потом код.

Мы не переписываем проект.

Мы постепенно превращаем существующую систему в цифрового консультанта, который принимает решения так же, как опытный специалист.

Каждый этап должен:

- быть небольшим;
- завершаться рабочим состоянием проекта;
- сопровождаться проверкой;
- заканчиваться отдельным Git-коммитом.

=========================================================
Главный принцип развития
=========================================================

Каждое изменение должно улучшать понимание человека системой.

Мы не добавляем функции ради функций.

Мы строим архитектуру, которая постепенно приближается к процессу мышления консультанта.

=========================================================
Главный принцип рефакторинга
=========================================================

Запрещается:

- большие переписывания проекта;
- изменение нескольких архитектурных узлов одновременно;
- рефакторинг "на будущее";
- изменение поведения системы без необходимости.

Разрешается:

- небольшие локальные изменения;
- выделение ответственности;
- постепенный перенос логики;
- создание новых компонентов только при появлении у них собственной ответственности.

=========================================================
Этап 1
Human Model становится ядром системы
=========================================================

Цель:

Сделать Human Model главным объектом архитектуры.

Все остальные компоненты работают только ради изменения Human Model.

На этом этапе:

- уточняется структура Human Model;
- определяется ответственность каждого Engine относительно Human Model;
- проект перестаёт мыслить сообщениями и начинает мыслить состоянием понимания человека.

Приоритет:

Максимальный.

=========================================================
Этап 2
Вероятностная Human Model
=========================================================

Цель:

Перевести Human Model от хранения полей к хранению гипотез.

Вместо:

Главная мотивация = здоровье

используется:

здоровье — 0.45

внешность — 0.35

страх болезни — 0.20

Каждая гипотеза получает уровень уверенности.

Human Model становится живой моделью понимания человека.

=========================================================
Этап 3
Reasoning Engine
=========================================================

Главная задача:

Не анализировать сообщения.

А постоянно отвечать на вопросы:

- Что стало понятнее?
- Какая гипотеза усилилась?
- Какая ослабла?
- Что остаётся неизвестным?
- Какая информация принесёт максимальный прирост понимания?

Reasoning Engine становится интеллектуальным ядром системы.

=========================================================
Этап 4
Decision Engine
=========================================================

Главная задача:

Принимать решения не о следующем вопросе.

А о следующем шаге понимания человека.

Decision Engine выбирает область Human Model с максимальной неопределённостью.

Например:

- мотивация;
- страх;
- ограничения;
- самооценка;
- доверие.

Именно это определяет дальнейшее развитие консультации.

=========================================================
Этап 5
Discovery
=========================================================

Discovery больше не имеет собственного сценария.

Он полностью зависит от состояния Human Model.

Если понимание недостаточно —

система исследует человека.

Если понимание достигло необходимой глубины —

Discovery завершается естественным образом.

=========================================================
Этап 6
Impact Engine
=========================================================

Impact Engine перестаёт быть генератором красивых формулировок.

Его задача —

определить, какое главное осознание должен получить человек именно сейчас.

Impact начинает работать только тогда, когда Human Model накопила достаточное понимание.

=========================================================
Этап 7
Emotional Engine
=========================================================

Emotional Engine определяет способ передачи выбранной мысли.

Он отвечает за:

- стиль общения;
- уровень эмпатии;
- темп разговора;
- эмоциональную глубину;
- степень поддержки.

Он не принимает решений.

Он помогает донести уже принятое решение.

=========================================================
Этап 8
Развитие памяти
=========================================================

Память постепенно разделяется на самостоятельные компоненты.

Human Profile

↓

Conversation State

↓

Conversation History

↓

Long-Term Memory

Human Model не является памятью.

Она создаётся заново после каждого сообщения на основе доступной информации.

=========================================================
Правила каждого изменения
=========================================================

Перед изменением:

1. Анализ.
2. План.
3. Минимальное изменение.

После изменения:

1. Запуск проекта.
2. Проверка работы.
3. Git Commit.
4. Git Push.

Только после этого начинается следующий этап.

=========================================================
Что НЕ делаем
=========================================================

Не переписываем dialog_engine.py целиком.

Не создаём сложные абстракции заранее.

Не переносим ответственность сразу в несколько новых модулей.

Не изменяем поведение системы без необходимости.

Не внедряем новый Engine, пока для него не появилась самостоятельная ответственность.

=========================================================
Главная цель проекта
=========================================================

Мы строим не чат-бота.

Мы строим цифрового консультанта.

Главная ценность проекта заключается не в генерации текста.

Главная ценность проекта — воспроизведение процесса мышления опытного консультанта.

После каждого сообщения система должна лучше понимать человека.

Ответ пользователю является следствием этого понимания.
